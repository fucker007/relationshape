# 聊天记录问题分析

## 问题1：Profile 摘要不完整 ❌

**现象**：
```
[召回·Profile] **喜好**：吃凡、吃饭、听歌、摇滚音乐、哭泣乐队
```

**实际存储**（:memories 显示）：
```
💚 喜好: 吃凡, 吃饭, 听歌, 摇滚音乐, 哭泣乐队, 重金属, 出去转转, 花, 春天的有才华, 油菜花, 向日葵, 看花
```

**根本原因**：
- Profile 摘要只显示前 5 个喜好
- 但实际存储了 12 个喜好
- 新增的喜好（重金属、出去转转、花、油菜花、向日葵、看花）没有显示在 LLM 上下文中

**影响**：
- LLM 无法看到完整的用户偏好
- 导致回复不够准确（例如问"我喜欢什么花"时，系统不知道用户喜欢油菜花、向日葵）

---

## 问题2：Preference 污染 ❌

**现象**：
```
[后台·属性] preference+=kfc
[后台·属性] preference+=饺子
[后台·属性] preference+=蜂蜜芥末
```

**问题**：
- "蜂蜜芥末" 不是偏好，而是 **调味料/蘸料**
- 应该被过滤掉（类似 P1 中的关系词过滤）

**根本原因**：
- LLM 提取时把"我喜欢吃蜂蜜芥末的"理解为偏好
- 缺少对"调味料、配菜、蘸料"的过滤规则

---

## 问题3：时间理解混乱 ❌

**用户说**：
```
我明天要去上学了,我一般是9月份开学
```

**系统理解**：
```
[后台·事件] summary="用户明天要去上学"
```

**问题**：
- 用户说的是"一般9月份开学"（周期性事实）
- 系统理解成"明天要去上学"（具体事件）
- 这是 **时间表达理解错误**

**根本原因**：
- LLM 没有区分"一般/通常"vs"明天/具体时间"
- 缺少对周期性事实的识别

---

## 问题4：事件去重不足 ❌

**现象**：
```
[daily] 用户想去东京
[daily] 用户想明天去旅游
[daily] 用户明天出去玩没空吃
```

**问题**：
- 这三个事件本质上是同一件事（都是关于旅游计划）
- 但被存储为 3 个独立事件
- 导致 Focus 中"旅行"被计数为 x2（应该是 x1）

**根本原因**：
- 事件提取时没有做去重/合并
- 相似事件应该合并或更新，而不是新增

---

## 问题5：Profile 摘要生成逻辑 ❌

**现象**：
```
[召回·Profile] **喜好**：吃凡、吃饭、听歌、摇滚音乐、哭泣乐队
```

**问题**：
- 只显示前 5 个，但没有"..."提示还有更多
- 新增的喜好完全被忽略

**应该**：
```
**喜好**：吃凡、吃饭、听歌、摇滚音乐、哭泣乐队、重金属、出去转转、花、油菜花、向日葵、看花（11项）
```

或者按 **recency/frequency** 排序：
```
**喜好**：油菜花、向日葵、花、蜂蜜芥末、kfc、饺子、...
```

---

## 问题6：LLM 上下文不同步 ❌

**现象**：
```
[后台·属性] preference+=蜂蜜芥末
[后台·完成] 644ms

[召回·Profile] **喜好**：吃凡、吃饭、听歌、摇滚音乐、哭泣乐队
```

**问题**：
- 后台刚更新了 preference
- 但下一次召回时，Profile 摘要还是旧的
- 说明 Profile 摘要没有实时更新

**根本原因**：
- Profile 摘要是缓存的，不是动态生成
- 缓存没有在属性更新时失效

---

## 问题7：Focus 权重计算错误 ❌

**现象**：
```
[后台·Focus] top=旅行(x2,positive)
```

**问题**：
- 用户提到旅行 3 次（想去日本、想去东京、明天出去玩）
- 但 Focus 显示 x2
- 说明有一次没有被计数

**根本原因**：
- 事件去重导致的（见问题4）
- 或者 Focus 更新逻辑有 bug

---

## 问题8：Stated vs Revealed 不匹配 ❌

**现象**：
```
用户说：我喜欢什么花?
系统回复：你之前提到过喜欢花，但具体喜欢哪种花我记不太清了
```

**实际存储**：
```
💚 喜好: ... 花, 春天的有才华, 油菜花, 向日葵, 看花
```

**问题**：
- 系统明明存储了"油菜花、向日葵"
- 但回复时说"记不太清"
- 这是 **Stated vs Revealed 的混淆**

**根本原因**：
- Profile 摘要不完整（问题1）
- LLM 看不到完整的喜好列表

---

## 优先级排序

| 优先级 | 问题 | 影响 | 修复难度 |
|-------|------|------|--------|
| **P3.1** | Profile 摘要不完整 | 高 | 低 |
| **P3.2** | Preference 污染（调味料） | 中 | 低 |
| **P3.3** | 时间理解混乱 | 中 | 中 |
| **P3.4** | 事件去重不足 | 中 | 中 |
| **P3.5** | Profile 缓存不同步 | 中 | 低 |
| **P3.6** | Focus 权重计算错误 | 低 | 低 |
| **P3.7** | Stated vs Revealed 混淆 | 中 | 低 |

---

## 修复方案

### P3.1：Profile 摘要完整性
- 显示所有喜好（或按 recency 排序显示 top 10）
- 添加"(N项)"标记

### P3.2：Preference 污染
- 添加 EXCLUDE_PREFERENCES 过滤规则
- 包含：调味料、配菜、蘸料、口味等

### P3.3：时间理解
- 在 LLM 提示中添加"一般/通常"识别规则
- 区分周期性事实 vs 具体事件

### P3.4：事件去重
- 在事件提取后做相似度检查
- 相似事件合并或更新

### P3.5：Profile 缓存
- 在属性更新时清除缓存
- 或改为动态生成

### P3.6：Focus 权重
- 检查 Focus 更新逻辑
- 确保每次提及都被计数

### P3.7：Stated vs Revealed
- 在 Profile 摘要中区分来源
- 标记"用户明确说过"vs"从事件推断"
